Determine Issue Type from the requester's primary outcome. Do not change an already populated Issue Type, except for an email-verification request: override an existing business or sales Issue Type when the requester is asking whether a specific email, sender, link, or attachment is safe, suspicious, spam, or phishing. Use Email for verification-only requests. Use Security only when the requester reports interaction or evidence of compromise, such as clicking a link or attachment, credential submission, malware execution, account compromise, or data exposure. When malicious intent or user-interaction risk is unclear, favor the more security-relevant classification over Spam.
